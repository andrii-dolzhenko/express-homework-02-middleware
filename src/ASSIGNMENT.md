# Розширення існуючого Express сервера за допомогою мідлварів

**Складність**: Висока  
**Базис**: Існуючий RESTful API сервер (всі базові тести пройдені)

## Мета завдання

Розширити існуючий функціональний Express.js сервер шляхом інтеграції системи мідлварів для логування, аутентифікації, валідації даних та управління правами доступу, зберігаючи сумісність з існуючими тестами.

## Нові вимоги для реалізації

### 1. Система мідлварів

Додайте до існуючого сервера такі мідлвари:

#### 1.1 Мідлвар логування (`logRequests`)

- **Призначення**: Записує детальну інформацію про кожен HTTP запит
- **Функціональність**:
  - Логування дати/часу, HTTP методу, URL, IP адреси, User-Agent
  - Для POST та PUT запитів додатково логує тіло запиту
  - Застосовується глобально до всіх маршрутів
- **Приклад реалізації**:

```javascript
function logRequests(req, res, next) {
  const timestamp = new Date().toISOString()
  const userAgent = req.headers['user-agent'] || 'Unknown'
  const ip = req.ip || req.connection.remoteAddress || 'Unknown'

  console.log(`[${timestamp}] ${req.method} ${req.url} - IP: ${ip} - User-Agent: ${userAgent}`)

  if ((req.method === 'POST' || req.method === 'PUT') && Object.keys(req.body).length > 0) {
    console.log(`  Request body:`, JSON.stringify(req.body))
  }

  next()
}
```

#### 1.2 Мідлвари аутентифікації

- **`demoAuth`**: Демонстраційний мідлвар аутентифікації

  - Логує наявність заголовка `Authorization`
  - Дозволяє проходження запитів (для сумісності з тестами)
  - Виводить попередження якщо аутентифікація відсутня

- **`strictAuth`**: Строгий мідлвар аутентифікації
  - Активується через заголовок `x-require-auth: true`
  - Перевіряє формат `Authorization: Basic <credentials>`
  - Повертає 401 при відсутності або неправильному форматі

#### 1.3 Мідлвари валідації даних

- **`validateUserData`**: Розширена валідація користувачів

  - Перевірка наявності та типу поля `name`
  - Додаткова перевірка довжини (максимум 100 символів)
  - Нормалізація даних (trim)

- **`validateArticleData`**: Розширена валідація статей
  - Перевірка наявності та типу поля `title`
  - Додаткова перевірка довжини (максимум 200 символів)
  - Нормалізація даних (trim)

#### 1.4 Мідлвар управління доступом (`demoArticleAccess`)

- **Призначення**: Контроль доступу до операцій зі статтями
- **Функціональність**:
  - Демонстраційний режим (за замовчуванням)
  - Строгий режим (через заголовок `x-require-strict-access: true`)
  - Перевірка ролі адміністратора для видалення статей
  - Повертає 403 при недостатніх правах у строгому режимі

#### 1.5 Мідлвари перевірки існування ресурсів

- **`checkUserExists`**: Перевірка існування користувача з логуванням
- **`checkArticleExists`**: Перевірка існування статті з логуванням

### 2. Інтеграція мідлварів з маршрутами

Оновіть існуючі маршрути, додавши відповідні мідлвари:

```javascript
// Користувачі
app.post('/users', demoAuth, strictAuth, validateUserData, ...)
app.put('/users/:userId', demoAuth, strictAuth, checkUserExists, validateUserData, ...)
app.delete('/users/:userId', demoAuth, strictAuth, checkUserExists, ...)

// Статті
app.post('/articles', demoAuth, demoArticleAccess, validateArticleData, ...)
app.put('/articles/:articleId', demoAuth, demoArticleAccess, checkArticleExists, validateArticleData, ...)
app.delete('/articles/:articleId', demoAuth, demoArticleAccess, checkArticleExists, ...)
```

### 3. Демонстраційні маршрути

Додайте нові маршрути для демонстрації строгих мідлварів:

```javascript
// Строга аутентифікація
POST /users/strict - створення користувача з обов'язковою аутентифікацією
POST /articles/strict - створення статті з обов'язковою аутентифікацією та контролем доступу
```

### 4. Тестування мідлварів

Для перевірки коректності роботи мідлварів додано автоматизовані тести. Щоб перевірити своє рішення, запустіть:

```bash
yarn test --run
```

Ви також можете тестувати функціональність вручну за допомогою `curl`:

```bash
# Звичайний режим (проходить тести)
curl -X POST http://localhost:3000/users -H "Content-Type: application/json" -d '{"name":"Test User"}'

# Строгий режим без аутентифікації (401)
curl -X POST http://localhost:3000/users/strict -H "Content-Type: application/json" -d '{"name":"Test User"}'

# Строгий режим з аутентифікацією (201)
curl -X POST http://localhost:3000/users/strict \
  -H "Content-Type: application/json" \
  -H "Authorization: Basic dGVzdDp0ZXN0" \
  -d '{"name":"Test User"}'
```

### 5. Важливі принципи реалізації

#### 5.1 Сумісність з тестами

- Мідлвари повинні бути "м'якими" за замовчуванням
- Строгі перевірки активуються через спеціальні заголовки
- Існуючі тести повинні проходити без змін

#### 5.2 Порядок підключення мідлварів

```javascript
// 1. Глобальні мідлвари
app.use(logRequests)

// 2. Мідлвари для конкретних маршрутів
app.post('/users', demoAuth, strictAuth, validateUserData, handler)

// 3. Обробники помилок (після всіх маршрутів)
app.use(errorHandler)
```

#### 5.3 Консольне виведення

Сервер повинен надавати інформативне виведення при запуску:

- Список всіх доступних маршрутів
- Опис функціональності мідлварів
- Приклади тестування строгих режимів

### 6. Технічні вимоги

- **Збереження функціональності**: Всі існуючі тести повинні проходити
- **Демонстраційність**: Додані мідлвари повинні показувати свою роботу через console.log
- **Гнучкість**: Можливість увімкнення строгих режимів через заголовки
- **Розширюваність**: Архітектура повинна дозволяти легке додавання нових мідлварів
